# Context — Training → Production & HuggingFace Publishing

On-demand detail for the training/HF rules in `AGENTS.md`. Governing ADRs: [ADR-012](../superpowers/adrs/ADR-012-training-to-production-delivery-hardening.md), [ADR-079](../superpowers/adrs/ADR-079-hf-jobs-m2m-oauth-training-auth.md), [ADR-080](../superpowers/adrs/ADR-080-training-sp-grants-and-model-ownership.md), [ADR-081](../superpowers/adrs/ADR-081-terraform-managed-training-experiments.md), [ADR-014](../superpowers/adrs/ADR-014-hf-card-inventory-parity.md), [ADR-054](../superpowers/adrs/ADR-054-hf-dataset-per-provider-configs.md), [ADR-049](../superpowers/adrs/ADR-049-restricted-hf-dataset-companion-repos.md), [ADR-064](../superpowers/adrs/ADR-064-per-match-access-tier.md), [ADR-072](../superpowers/adrs/ADR-072-publish-seam-guarded-frame.md).

- **Training-to-production delivery contract** ([ADR-012](../superpowers/adrs/ADR-012-training-to-production-delivery-hardening.md)): Every training script that targets the Databricks inference path MUST import from `ingestion.artifact_deploy` and call all three helpers — `require_mlflow_env()` at the top of `main()` (no silent `if tracking_uri:` gate), `set_and_verify_mlflow_champion(...)` after `mlflow.pyfunc.log_model` (zombie-alias guard), and `upload_weights_to_uc_volume(...)` after the HF Hub publish (the consumer's UC Volume fallback is NOT optional). Training invocations via `hf jobs uv run` MUST pass secret-valued env vars via `--secrets` (encrypted), never `--env` (plain metadata visible via `hf jobs inspect`). `require_mlflow_env` accepts EITHER a static `DATABRICKS_TOKEN` OR M2M OAuth service-principal creds (`DATABRICKS_CLIENT_ID`+`DATABRICKS_CLIENT_SECRET`); the M2M form auto-refreshes inside the job and is REQUIRED for any run longer than an OAuth access token's ~1h TTL ([ADR-079](../superpowers/adrs/ADR-079-hf-jobs-m2m-oauth-training-auth.md)). SQL-reading trainers (ScoutGPT, xtgk-v2) source their bearer via `ingestion.databricks_auth.bearer_token()` (M2M-aware), never `os.environ["DATABRICKS_TOKEN"]`. The SP's training-write grants — MLflow-experiment `CAN_EDIT` + UC registered-model ownership + gold-schema `CREATE_MODEL` for the `dbt-owners-{env}` group — are codified in Terraform (`databricks_permissions.*_experiment_acl`, `dbt_owners_gold_select`) because `databricks_permissions` is AUTHORITATIVE and reverts ad-hoc grants on the next `terraform apply`; UC-model ownership is normalized by `scripts/normalize_training_model_ownership.py`. The experiment itself is a TF-managed `databricks_mlflow_experiment` **resource** (not a `data` lookup) so a fresh `terraform apply` CREATES it ([ADR-081](../superpowers/adrs/ADR-081-terraform-managed-training-experiments.md)). Adding a new training model REQUIRES its experiment RESOURCE + experiment ACL + a `TRAINING_MODELS` entry + a `test_training_grants_conformance.py` case ([ADR-080](../superpowers/adrs/ADR-080-training-sp-grants-and-model-ownership.md), [ADR-081](../superpowers/adrs/ADR-081-terraform-managed-training-experiments.md)). Any PEP 723 script is single-file — sibling imports do NOT work on HF Jobs; helpers that need to travel with the script must be inlined.

- **Model weights envelope feature_names convention** (ADR-012 §2): Model weight serialization formats that do not natively embed feature names (e.g., the NumPy-dump envelope used by `analytics.set_encoder.serialize_set_encoder_weights`) MUST inject a top-level `feature_names: list[str]` field into the JSON envelope. Inference reads it and reindexes tabular input. XGBoost is exempt because the booster binary already carries feature_names via `get_booster().feature_names`. **Grace-period closure (2026-05-02, SK3-MIG):** the v2→v1 feature-list fallback was removed so legacy envelopes without `feature_names` raise `RuntimeError` at inference. The canonical pre-shot xG path is now `ingestion.xg_shot_scorer` (`xg_model_v3`), trained by `scripts/train_xg_v3_hf.py` (injects `tabular_dim` alongside `feature_names`). The legacy `ingestion.xg_model_v2` + `scripts/train_xg_v2_hf.py` were retired 2026-07-10 (ADR-066). See [ADR-022](../superpowers/adrs/ADR-022-direction-of-play-migration.md).

- **HuggingFace Hub**: Org is `luxury-lakehouse`. Model artifacts cached in UC Volume `/Volumes/soccer_analytics/dev_gold/model_weights/`. Set `HF_HOME` env var for local cache location. Use `huggingface_hub` for model publish/download (no torch dependency).

- **HF READMEs ride with payload via `ingestion.hf_publish`** ([ADR-014](../superpowers/adrs/ADR-014-hf-card-inventory-parity.md)): every publisher that creates or refreshes a HF dataset / model / Space repo MUST call `ingestion.hf_publish.upload_hf_readme(...)` after the data/weight upload, passing a card resolved via `get_hf_card_path(name, kind=...)`. In-repo card filename must equal the HF repo basename (filename == repo basename invariant). Missing cards + orphan cards are caught by `src/tests/test_hf_publish_parity.py`. Orphan-only push paths go through `scripts/publish_hf_cards.py --org` / `--orphans` / `--name --kind`. Never re-implement the README push inline in a publisher — the helper is the only path.

- **Per-provider HF dataset configs via flat layout + dynamic card injection** ([ADR-054](../superpowers/adrs/ADR-054-hf-dataset-per-provider-configs.md)): multi-provider HF datasets publish FLAT per-provider files (`data/<provider>.parquet`, keeping the `data_source` column — NOT Hive `data/data_source=<p>/data.parquet`), and the card's `configs:` block (a default `all` + one config per provider) is INJECTED AT PUBLISH TIME from the providers actually present — never a static list in the card. Mechanism lives in `ingestion.hf_publish`: `build_provider_configs(providers)` + `inject_frontmatter_configs(card, cfgs)` + `upload_hf_readme(..., config_providers=…)`. First applied to `publish_action_context_hf.py`. Tests: `test_hf_publish.py::TestProviderConfigInjection`.

- **HF redistribution restriction is PER-MATCH via `access_tier`** ([ADR-064](../superpowers/adrs/ADR-064-per-match-access-tier.md), building on [ADR-049](../superpowers/adrs/ADR-049-restricted-hf-dataset-companion-repos.md)'s permanent private companion repos): the split key is a per-row `access_tier` (`public`/`restricted`) classified by the pure stdlib core `shared.access_tier.classify_access_tier(provider, visibility)` (`"private"`/unknown → RESTRICTED fail-safe; `"public"` → PUBLIC; `None` → a fail-safe ALLOWLIST: PUBLIC only for `PUBLIC_BY_LICENSE_PROVIDERS` (statsbomb/wyscout/idsse/metrica) — everything else fails safe to RESTRICTED). Ingestion stamps raw `visibility` + derived `access_tier` on bronze and it rides per-row through SPADL/AC/tracking/psxg → marts. `split_restricted(df, column="access_tier")` splits fail-safe (NULL/unknown → restricted). Since [ADR-072](../superpowers/adrs/ADR-072-publish-seam-guarded-frame.md) publishers NEVER call `split_restricted` / `assert_no_private_leak` / the `access_tier` drop themselves — all three happen inside `ingestion.hf_upload_seam.prepare_public_upload(df, publisher=...)`, which returns `GuardedFrame`s that are the only objects able to write a Parquet; `upload_guarded(staging_dir, frames=[...], ...)` refuses any staged file no receipt accounts for and derives repo privacy from the frame tier. Direct `HfApi` use, `GuardedFrame(...)` construction and `dataclasses.replace` are AST-banned in `publish_*_hf.py` (`test_publisher_seam_conformance.py`). A publisher missing from `PUBLISHER_REGISTRY` fails the test, and the discovery count is pinned at 15. `upload_folder` delete patterns must be `["**"]` (matched RELATIVE to `path_in_repo`) — four publishers violated this with `["data/*"]` and had silently swept NOTHING until ADR-072 corrected them. Enforced by `test_hf_leak_guard.py`, `test_hf_publish.py`, `test_hf_publish_parity.py`, `test_gradientsports_hf_exclusion.py`, `test_pining_visibility_contract.py`, and `test_publisher_seam_conformance.py` + `test_publisher_upload_contract.py`.
