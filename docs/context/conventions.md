## Type Safety

- **Pyright basic mode**: All Python code must pass `pyright` in basic type checking mode.
- **Pydantic models**: Use where appropriate for configuration and data contracts.

## Project Conventions

- **Python 3.10 (locked)**: Pinned to `>=3.10,<3.11` in `pyproject.toml` and `.python-version`. Databricks serverless only supports Python 3.10. Run `uv sync` to get a 3.10 venv automatically.
- **Imports**: stdlib → third-party → first-party, enforced by isort.
- **Entry points**: Each ingestion module exposes a `main()` function registered in `pyproject.toml`.
- **Delta tables**: All bronze writes include `_ingested_at` audit column with UTC timestamp.
- **Partition overwrite**: Use `replaceWhere` for incremental loads, not full table overwrites.
- **Pre-compile regex at module level**: Never use `re.compile()`, `re.sub()`, or `re.match()` with raw pattern strings inside function bodies or loops. Compile patterns as module-level constants.
- **Serverless env deps are EXACT pins synced to uv.lock** ([ADR-046](../superpowers/adrs/ADR-046-serverless-env-exact-pins.md)): every PyPI dep in `terraform/modules/workflows/main.tf` `environment` blocks uses `==` mirroring `uv.lock`. Bumping a library = pyproject + `uv lock` + `python scripts/sync_tf_env_pins.py`; `src/tests/test_terraform_env_dep_parity.py` sentinels enforce `==`-only + lock-parity. The CI dbt pins ride the same lockstep, and `scripts/ci/run_dbt_in_databricks.py` is NOT executed from the checkout — the task runs a copy deployed by `scripts/upload_ci_shim.py`. Generally: an artifact that runs from a mutable location outside the repo is covered by no repo-side test — verify the deployed copy.
- **uv silent-downgrade footgun in PEP 723 deps**: uv does NOT fail-fast on conflicting top-level vs wheel-transitive dep pins. The top-level pin wins silently. Prefer letting the wheel's `[spadl]` extra be the single source of truth. If a PEP 723 script must pin a project-owned library, its `main()` MUST add a runtime version assertion (see `scripts/train_*_hf.py`'s `_REQUIRED_SK_MIN` check). Sentinel: `src/tests/test_sk3_mig_b_orchestrator_invariants.py`.
- **SPADL post-conversion enrichments live in `src/ingestion/spadl_enrichments.py`** ([ADR-016](../superpowers/adrs/ADR-016-spadl-enrichment-stage-canonical-naming.md)): new helpers added to `apply_spadl_enrichments` + a column added to `_SPADL_SCHEMA` + `_VAEP_SCHEMA` + applyInPandas StructTypes (parity-tested via `test_spadl_vaep_writer_parity.py`). Provider-native passthroughs use `<provider>_<field>`; computed enrichments use plain canonical names; native string identifiers paired with Kimball surrogates use `<entity>_native`. For IDSSE/Metrica/SkillCorner string identifiers, the legacy BIGINTs `match_id` and `team_id` carry `hash_native_id_to_bigint(native_id)` (deterministic SHA-256[:15]). NULL `team_id_native` edge cases get sentinel hash `UNKNOWN_TEAM_SENTINEL` with a warning log.
- **A driver-bound sub-operation gets its OWN task, and standalone-capability is NOT free** ([ADR-074](../superpowers/adrs/ADR-074-hf-sync-process-isolation-and-memory-observability.md)): `hf_sync` runs its sub-operations in ONE driver process, so their memory is cumulative — it was OOM-killed (`exit 137`) while the publisher that died measured only 6.97 GB of ~16 GB alone. Anything pulling a multi-million-row mart to the driver via `.toPandas()` belongs in its own task. `_STANDALONE_MODULES` is hardcoded; `hf_sync` is now export-only (`test_hf_sync_is_export_only`). Driver memory is reported for EVERY `@workflow` by `ingestion.memory_hook.MemoryHook`. Cards must state the environment their task actually runs in (`test_card_phase_environments_match_terraform`).
- **Medallion layer schemas are NAMED, and a swallowed sub-workflow still FAILS ITS TASK** ([ADR-073](../superpowers/adrs/ADR-073-layer-schemas-named-and-hf-sync-fails-loud.md)): use `DEFAULT_BRONZE_SCHEMA` / `DEFAULT_SILVER_SCHEMA` / `DEFAULT_GOLD_SCHEMA` from `shared.constants` and name the layer at the point of use. Workflow cards pin it too — `resolve_upstream_tables_from_card` substitutes `{schema}`; watermark upstreams must be TABLES (`DESCRIBE HISTORY` rejects views). `hf_sync`'s per-op `except Exception` stays, but `run_pipeline` MUST call `raise_on_failed_sub_workflows`. Enforced by `src/tests/test_layer_schema_conformance.py`.
- **Bronze migrations under `scripts/migrations/*.sql` are operator-applied — there is NO CI auto-apply.** Apply each new migration manually with the merge via `uv run --extra sdk python scripts/migrations/_runner.py scripts/migrations/<file>.sql`. Only single-leading-column `ALTER TABLE ADD COLUMNS` is made idempotent (DESCRIBE skip-if-exists); every migration MUST still be idempotent by construction. Destructive ops remain operator-driven. Always verify with a live `DESCRIBE`/`SELECT` post-apply.
