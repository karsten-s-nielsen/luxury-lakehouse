# Context — Action-Context & silly-kicks Integration

On-demand detail for the Action-Context rules in `AGENTS.md`. Governing ADRs: [ADR-022](../superpowers/adrs/ADR-022-direction-of-play-migration.md), [ADR-029](../superpowers/adrs/ADR-029-silly-kicks-4-et-direction-adoption.md), [ADR-030](../superpowers/adrs/ADR-030-gradient-sports-bronze-frame-dedup.md), [ADR-053](../superpowers/adrs/ADR-053-silly-kicks-4-27-0-geometric-frame-ltr-net.md), [ADR-067](../superpowers/adrs/ADR-067-velocity-delete-and-depend-and-unit-write-atomicity.md), [ADR-068](../superpowers/adrs/ADR-068-ac-unit-events-and-drain-completeness-gate.md), [ADR-087](../superpowers/adrs/ADR-087-drain-circuit-breaker-and-canary.md).

- **silly-kicks 3.0.1+ direction-of-play kwargs** (ADR-022): Sportec + Metrica converters require explicit `home_team_start_left` (or `home_attacks_right_per_period` mapping) per silly-kicks 3.0.1's `convert_to_actions(...)` API. Lakehouse derives the bool via two helpers in `src/ingestion/spadl_adapter.py`: `derive_idsse_home_team_start_left` reads `kickoff_team_left` from the IDSSE bronze KickOff event row (authoritative — DFL XML); `derive_metrica_home_team_start_left` infers from period-1 SHOT positions (empirical — Metrica bronze does not capture a kickoff-side flag). Both raise loud on insufficient signal. Canonical SPADL LTR invariant (both teams' shots cluster at high-x post-conversion) is regression-gated by `src/tests/test_sk3_coord_correctness.py`. Strict-mode env var `SILLY_KICKS_ASSERT_INVARIANTS=1` is set process-wide via `src/ingestion/bootstrap.py:os.environ.setdefault(...)` (Databricks serverless `compute.Environment` does not support per-job env vars natively); same env var also set at job level in CI workflows.

- **silly-kicks 4.0+ extra-time symmetric guard** (ADR-029): silly-kicks 4.0.0 adds `require_et_direction` across all 5 per-period-absolute converters (Sportec tracking + Sportec/Metrica/GS events + GS tracking) — raises on `period_id in {3, 4}` without `home_team_start_left_extratime`. Lakehouse-side ET derivers: `derive_idsse_home_team_start_left_extratime` reads DFL XML `extraTimeFirstHalf` KickOff; `derive_metrica_home_team_start_left_extratime` empirically infers from period-3 SHOT positions; GS carries the flag in bronze metadata. `MatchMeta.home_team_start_left_extratime` plumbs through to every `convert_to_frames` / `convert_to_actions` call site. `None` is safe when match has no ET periods. Set-piece restart actions get finite DAS via `src/analytics/action_context/enrich.py:_fill_possession_from_set_piece_actions` (lakehouse owns this modeling decision per the PR-S67 boundary; silly-kicks stays pure). Pre-flight sentinel `src/tests/action_context/test_et_direction_sentinel.py` asserts the pipeline path actually reaches the guard.

- **Action-context frame orientation = owned UPSTREAM by silly-kicks (geometric)** ([ADR-053](../superpowers/adrs/ADR-053-silly-kicks-4-27-0-geometric-frame-ltr-net.md) amended → ADR-034 TF-23 / ADR-035 TF-23b): the in-repo `analytics.action_context.pipeline.correct_frames_to_home_ltr` net is **DELETED** (TF-23, silly-kicks 4.34.0). Every tracking provider now comes out home-LTR from the converter: SkillCorner/Metrica via the silly-kicks `tracking.{skillcorner,metrica}.convert_to_frames` builders (adopted through `analytics.action_context.sk_frame_adapters`; geometric `orient_frames_to_ltr_by_geometry` runs when the orientation flags are omitted — which the AC adapters do); idsse/GS via the silly-kicks native adapters' geometric backstop (TF-23b, ADR-035). The invariant is unchanged (home GK at LOW x in home-LTR; per-period point-reflection `x→105−x, y→68−y`; speed invariant; period 5/PSO is never oriented). Do NOT re-introduce a lakehouse-side orientation net or pass `home_start_left` flags to the builders. Regression oracle: `src/tests/action_context/test_frame_orientation_golden.py` (cross-provider — recomputes a real idsse/skillcorner/GS-extra-time `10517_p3` slice through `_convert_tracking_batch` and asserts home-GK-low). The legacy `tracking_context.py`/`fct_tracking_context` (TC-1) pipeline is **RETIRED (PR-1)**: its two consumers were re-homed onto AC-1 (`int_tracking_goalkeepers` + `int_minutes_played_per_match`'s idsse leg now read `stg_action_context__values`, with a GK `n_actions>=2` mis-tag threshold), and the module / mart / staging / synced config / TF tasks / cards were deleted (bronze `spadl_tracking_context` DROP is operator post-merge). AC-1's frames ARE oriented, so the un-oriented-TC-1 caveat no longer applies.

- **Gradient Sports bronze writer dedup** ([ADR-030](../superpowers/adrs/ADR-030-gradient-sports-bronze-frame-dedup.md)): The GS provider ships content-divergent duplicate `(period, frameNum)` records (up to 16 copies per frame in match 10502). `src/ingestion/gradientsports_tracking.py:_iter_unique_frames` does keep-first dedup at the bronze writer — the lakehouse's data-quality boundary. NO adapter-level dedup; NO per-feature dedup. silly-kicks 4.0.1's bekkers defense-in-depth is complementary, not a replacement. Synthetic 16-copy regression at `src/tests/test_gradientsports_ingestion.py::TestFrameDedup`. After provider-side bronze changes, existing GS bronze must be re-ingested for the dedup to apply to already-stored data.

- **Tracking velocity/preprocess is silly-kicks-owned — never re-add a lakehouse copy** ([ADR-067](../superpowers/adrs/ADR-067-velocity-delete-and-depend-and-unit-write-atomicity.md)): `_derive_velocities_savgol` is DELETED from `analytics/action_context/convert.py` (it was also deleted from `ingestion/tracking_context.py`, now itself RETIRED with the TC-1 pipeline in PR-1). SkillCorner/Metrica derive velocity through the silly-kicks builders' `preprocess=` seam (the one GS/IDSSE already used). The port had dropped upstream's `len(x_vals) <= 1` guard, so a 1-frame player track crashed `np.gradient` and zeroed a whole work unit (0 of 550 actions, inside a job that reported SUCCESS). **Always pass `PreprocessConfig.default()`** — `is_default()` is FLAG-based (set only by the `.default()` factory), so a hand-built `PreprocessConfig(derive_velocity=True)` is passed through UNPROMOTED and silently uses the universal `sg_window_seconds=0.4` instead of the per-provider tuning. Never import `silly_kicks.tracking.preprocess._resolve` (private); use `PreprocessConfig.for_provider()`. Enforced by `test_convert_drift.py::test_velocity_helper_is_deleted_and_depended` + `test_velocity_single_frame.py`.

- **A drain worker that swallows a unit failure must still FAIL ITS TASK** ([ADR-067](../superpowers/adrs/ADR-067-velocity-delete-and-depend-and-unit-write-atomicity.md)): the per-unit `except Exception` in `analytics/action_context/drain.py` is deliberate and stays (one bad unit must not destroy a 5.5 h drain; the slice rolls forward), but `main_drain_worker` MUST call `raise_on_failed_units(summary, run_id=...)` after logging. Without it a raised guard and a silently-passing invariant are INDISTINGUISHABLE from the mart. Timeouts are excluded (they roll forward by design). When a pipeline silently produced no rows, read the per-iteration driver log (`ac1_drain_unit_failed`) FIRST, not the mart. Since ADR-068 there is a more direct answer: query `observability.action_context_unit_events` or read the `verify_action_context_drain` gate's report.

- **AC unit events + the drain completeness gate** ([ADR-068](../superpowers/adrs/ADR-068-ac-unit-events-and-drain-completeness-gate.md)): the drain and the sb360 task append per-unit lifecycle events (`running` → terminal → `slice_completed`), and the fan-in `verify_action_context_drain` task (`run_if = ALL_DONE`) reads them back to prove every enumerated unit ran and its rows landed. Four rules, each of which was a bug first:
  - **`write_delta_table` DEFAULTS TO `mode="overwrite"`** — every event write MUST pass `mode="append"` explicitly. Enforced by an AST guard (`src/tests/_delta_write_ast.py`).
  - **`run_id` is `{{job.run_id}}` everywhere — NEVER the preflight task value.** Preflight is itself passed `{{job.run_id}}`, so the values are identical.
  - **Per-worker event tables + a UNION view, never one shared table** (8 concurrent writers p50 9,700 ms vs 1,656 ms single-writer — a 5.9× contention penalty). `ensure_tables()` belongs to **preflight** (a single writer) and must sit BEFORE its nothing-to-do early-return.
  - **Fail-open on unit events, fail-loud on `slice_completed`.** Event loss taints **that worker only** (`UNVERIFIABLE`), never the whole run — and `UNVERIFIABLE` requires a NON-EMPTY anomaly set (`all([])` is `True`).

- **A drain fast-fails a SYSTEMIC failure, and a systemic bug is caught BEFORE the fan-out** ([ADR-087](../superpowers/adrs/ADR-087-drain-circuit-breaker-and-canary.md)): the shared `drain_worker` fast-aborts a per-unit FAILURE storm — a hybrid circuit-breaker trips when `consecutive_failures >= max_consecutive_failures` (6) OR `failed/attempted > systemic_failure_rate` (0.5) after `systemic_min_sample` (20) attempts (timeouts excluded; a success resets the consecutive count). On trip it flushes terminals, emits `slice_completed(abort_reason=...)` and raises `DrainCircuitBreakerError` — BYPASSING `raise_on_failed_units`. Both the AC and tracking-marts preflights then run an in-preflight dry-run canary (`analytics.action_context.canary.run_canary`, one unit per provider, non-skippable) AFTER the nothing-to-do early return: `process(unit, dry_run=True)` computes every writer but persists nothing. This is how the `gk_decision` `is_actor` corpus-wide failure (654 units, ~5.5 h before manual cancel) is now caught in ~minutes.

- **The AC planners are a WELDED PAIR**: `_find_tracking_new_period_pairs` and `_find_idsse_new_period_pairs` (`ingestion/action_context.py`). An edit to one that is not mirrored in the other is a defect. Both join tracking (at `(match, period)` grain) against SPADL — the SPADL leg MUST also be period-grain (ADR-068; it was match-grain, so a period with frames but zero actions was enumerated as a unit that could never produce rows).
