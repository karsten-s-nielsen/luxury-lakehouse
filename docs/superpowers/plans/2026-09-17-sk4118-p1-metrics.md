# silly-kicks 4.118.0 Adoption — P1 New Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Materialize the eight new silly-kicks 4.118.0 metric families in the lakehouse — each as a full ADR-013 chain (Python writer → bronze → dbt staging view → gold mart with `contract: enforced: true`) plus governance, academic references, and UI — grain-bucketed into shared wide marts.

**Architecture:** Every new event-only metric mirrors the canonical `src/ingestion/bravery_writer.py` ADR-013 template: a module-level `_REQUIRED_SK_MIN`, a `*_METRIC_COLUMNS` tuple mirroring the sk package constant, a pure unit-tested `_compute_*_group`, an `applyInPandas` `run_pipeline` writing bronze with `replaceWhere`, and a `main()` gated by `require_sk`. Writers emit NATIVE ids; surrogate keys resolve in the mart via INNER JOIN on `dim_*`. Tracking metrics (gk_decision reconstruction tier, restdefense) run in the tracking-marts drain. Marts are wide-by-granularity (§4).

**Tech Stack:** Python 3.10, PySpark (Databricks serverless, `applyInPandas`), dbt (databricks, contracts), silly-kicks 4.118.0, Taipy (hf_taipy_app), HuggingFace Hub (ADR-072 guarded seam).

**Spec:** `docs/superpowers/specs/2026-09-17-silly-kicks-4118-adoption-design.md` (§4, §5, §7). Depends on **P0** (branch `feat/sk4118-adoption` already on 4.118.0). Executes on the same branch.
