# silly-kicks 4.118.0 Adoption — P2 Recompute & Verification Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (this is an operator-run plan, not TDD code). Steps use checkbox (`- [ ]`) syntax. EVERY run step is gated on explicit owner approval AND live Databricks auth.

**Goal:** After P0 (foundation) + P1 (metrics) are code-complete and merged, bring the existing match corpus onto 4.118.0 behavior and materialize the eight new marts — via an ordered set of operator recompute/re-fit runs — then verify the end state and close the two red CI jobs.

**Architecture:** No new application logic (that is P0/P1) — the only file change here is the wheel VERSION bump + its `bump_wheel.py` propagation (Task 1 Step 2), which is metadata that must ride the branch so the published wheel carries the P0/P1 code. This plan is otherwise the sequenced operator execution of spec §6, each step verified against LIVE Databricks state before the next (no deploy-and-observe). Runs are wheel-consuming, so they happen ONLY after post-merge CI is green (`[no-jobs-in-ci]`, `[wait-post-merge-ci]`).

**Tech Stack:** Databricks mega-job (`run_now(job_id, only=[task_key])`), `rederive_synced_marts.py`, HF Jobs training (`train_xt_gk_v2_hf`), dbt build, `system.billing.usage`.

**Spec:** `docs/superpowers/specs/2026-09-17-silly-kicks-4118-adoption-design.md` (§6, §8). Prereq: P0 + P1 merged; branch `feat/sk4118-adoption` squash-merged to `main`.

## Global Constraints

- **Live Databricks auth is a hard prerequisite.** The OAUTH profile refresh token was expired; owner is now LOCAL and can re-auth via `databricks auth login --profile OAUTH` (browser localhost redirect on the Windows machine). Run that (or `scripts/mint_databricks_oauth.py` once the CLI login is fresh) before the first operator step; confirm `.venv/Scripts/python.exe` can mint a token. No operator run proceeds without it.
- **Approval gate per run:** each recompute/re-fit/re-derive/publish is a discrete step needing a separate explicit owner "yes". Approval of this plan is not run authority.
- **No wheel-consuming job until post-merge CI is green.** Order: merge → post-merge CI + Terraform Apply green (new mega-job tasks + env pin exist) → then runs.
- **Recompute is over the EXISTING corpus only.** No new SB360/SkillCorner match ingestion.
- **Failure Investigation Protocol:** on the FIRST unexpected failure/hang, investigate root cause (service state + logs) before any retry. Report findings before fixes. Three-strikes = pattern.
- **Never disappear into long runs:** every run uses background polling; report progress every 15–30 s; the AC drain is ~5.5 h (watchdog per-half 2700 s) — poll the driver log (`ac1_drain_unit_failed`, `observability.action_context_unit_events`).
- **Re-deriving a TRIGGERED-synced mart:** NEVER `dbt --full-refresh`; use `scripts/rederive_synced_marts.py` (ADR-043).
