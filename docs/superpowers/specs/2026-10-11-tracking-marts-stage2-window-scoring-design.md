## 1. Problem

The tracking-marts drain (ADR-088 two-stage executor-distributed build) materializes six marts per `(match, period)` unit. **Stage-1 build is window-bounded** (ADR-089 haloed seam, `_TM_WINDOW_FRAMES=20000`) and the ADR-087 preflight Probe M proves the global densest build-window fits the serverless ~1 GB Python-worker UDF-group cap. **Stage-2 scoring is NOT window-bounded** — it re-reads the whole spilled unit and scores it in one pass. On a dense skillcorner unit this exceeds the cap.

## 2. Root cause

### 2.1 Stage-2 whole-unit regroup (the OOM)
`tracking_marts_dispatch.build_stage2_mart_sdf` (`tracking_marts_dispatch.py:263-290`) reads the spilled built frames and regroups them by **`keys = ["game_id", "period_id"]` = the whole unit, one group** (`:280`). The group is dispatched through `_make_streaming_group_mapper` (`src/ingestion/action_context.py:344-389` — distinct from the `src/analytics/action_context/` package), which **materializes the entire group as one pandas DataFrame** before calling the scorer: it `pd.concat`s chunks until the group key changes, then calls `udf_fn(group.reset_index(...))` on the full group (`:383-384`). For Stage-2 the group key never changes within a unit → the whole-unit built frame is coresident in the Python worker.

A dense unit's whole-unit built frame is ~583 MB (ADR-089 fit-profile: GS `10502:1` = 583 MB built / 83 950 frames, float32). A dense skillcorner unit is comparable. On top of that sit each scorer's working set (pitch-control / DAS grids). Whole-unit built frame + grids > ~1 GB cap → `[UDF_PYSPARK_ERROR.OOM]`.

**Stage-1 is ruled out by evidence:** `skillcorner ∈ SEAM_PROVIDERS` (`frame_windows.py:46`), so Stage-1 build runs through `windowed_build_sdf` bounded by `_TM_WINDOW_FRAMES=20000`; Probe M built the global densest build-window and the GATE-0 preflight SUCCEEDED (and R7 at 195 s). The only unbounded memory point is the Stage-2 whole-unit group.

ADR-089 §3 explicitly deferred this: Non-goal (b) "Changing the tracking-marts Stage-2 scorers". This cycle is that deferred work.

### 2.2 Retry-enforcement no-op (the DBU waste — Fix B)
`scripts/patch_job_retries.py` read `task.get("max_retries", 0)`. The Databricks Terraform provider drops `max_retries = 0` from the payload (Go `omitempty`), so a compute task's deployed setting is **ABSENT**, and the platform applies its default of **1 retry** for an absent field. Reading absent as `0` made the patcher decide "already 0" → **no reset sent** → the deployed tracking-marts tasks ran with 1 retry. In GATE-0 each OOM iteration retried once (a full re-drain of the slice) before the operator cancelled — the avoidable DBU burn. The existing `test_job_retry_policy.py` only checked classifier parity, so it did not catch the live no-op. (Fix in §4.7; already staged on `fix/patch-job-retries-absent-zero`.)

## 3. Goal / Non-goals

**Goal.** Make Stage-2 scoring memory-bounded by **window size, not unit size**, byte-identically to today's whole-unit scoring, so the 8 dense skillcorner units (and any future dense unit) materialize within the serverless UDF-group cap — and fold in the retry-enforcement fix so the release leaves live retries = 0.

**Non-goals.**
- (a) Re-implementing any scorer in Spark SQL — scorers stay the sk/ingestion pandas scorers.
- (b) Changing scorer outputs. The windowed result MUST equal the whole-unit result (neutrality, §6). Any metric change is out of scope and a blocker — **with ONE owner-ratified exception (§4.6a): actions BEYOND frame coverage.** An action that links to no frame (e.g. an event logged after tracking stops) is scored whole-unit only via a degenerate, frame-INDEPENDENT fallback (a zero-value credit, `n=1`) that a single window cannot reproduce; such actions are excluded identically in BOTH paths. In-coverage actions (every action that links to a frame — the metric population) stay byte-identical, so Non-goal (b) holds for them; only the degenerate beyond-coverage rows are dropped, with the owner's explicit approval.
- (c) Changing the drain unit-of-work off period-grain (the WELDED planner pair / completeness gate / replaceWhere keys are untouched).
- (d) Re-tuning `_TM_WINDOW_FRAMES` for Stage-1 (that is ADR-089's knob; Stage-2 gets its own scoring-window parameter, §4.5).
- (e) Perf optimization beyond what the memory fix requires. The gkdv unchunked-loop latency (§7 R5) is noted but only addressed if the memory change touches that path (measure-before-optimize, §6).

## 4. Design

### 4.1 Extend the ADR-089 haloed-window seam to Stage-2 scoring
Stage-2 currently groups the spilled built frames whole-unit. Replace that with a **scoring-windowed** dispatch symmetric to Stage-1's build seam: partition the spilled built frames into contiguous frame-windows, replicate a **scoring halo** of neighbouring built frames into each window, route each scored entity (action / keeper-frame) to the window of its linked frame, score each `(core + halo)` window, trim halo-origin outputs, and union the cores = the whole-unit mart output.

Two properties distinguish Stage-2 windowing from Stage-1 (§4.2–4.3):
1. The halo is a **scoring** halo (sized by each scorer's temporal reach), not the build halo (sized by sk's velocity/interpolation stencils). It is generally different and per-mart.
2. Three marts depend on **whole-unit invariants** (a GoalMap; gkdv's ball-carrier) that a per-window frame slice cannot reproduce. Those invariants are **precomputed once over the whole unit (cheaply) and injected** into the windowed scoring (§4.3). This is what preserves byte-identity.

The built frame carries `game_id (int64)`, `period_id (int64)`, `frame_id (int64)` (a per-frame dense ordinal, sk `TRACKING_FRAMES_COLUMNS`), so window assignment reuses the ADR-089 ordinal mechanism on `frame_id` (not the raw-bronze `frame`/`frame_num`, which exist only pre-build).

### 4.2 Per-mart windowability + scoring-halo (research-verified)

| Mart (entry point) | Output grain | Frame access | Scoring halo (reach) | Whole-unit invariant | Layer |
|---|---|---|---|---|---|
| `off_ball_runs_writer.compute_off_ball_runs` | (action, runner) | pre-action window scan + 1 linked frame | **1.5 s pre, 0 post** → `ceil(1.5·hz)` = **15** frames skillcorner/GS, **38** idsse (sk `_run_values.py` `pre_seconds=1.5`). Vs build halo (sk 16 / GS 9 / idsse 22): **larger for idsse (38>22) + GS (15>9); skillcorner 15 ≤ 16.** | none | lakehouse-only |
| `defensive_credit_writer.compute_action_defensive_credit` | per action | 1 linked frame (`merge_asof`) | link tolerance ~0.2 s (2–5 frames) | none | lakehouse-only |
| `defensive_credit_writer.compute_defensive_credit_long` | (action, player, rule) | 1 linked frame | link tolerance ~0.2 s | none | lakehouse-only |
| `restdefense_writer.compute_rest_defense_samples` | per on-ball action | 1 linked frame; defensive-line/team-shape are per-frame | link tolerance ~0.2 s | **GoalMap** — sk seam ALREADY exists (`compute_rest_defense(..., goal_map=None)`); thread it through | lakehouse-only |
| `gk_decision_writer.score_gk_decision_unit` | per decision | 1 linked frame | link tolerance | **GoalMap** — sk recomputes internally, **no param** → needs sk seam | **CROSS-REPO** |
| `gkdv_writer.score_gkdv_unit` | per scored keeper-frame | 1 frame pair (actual+ghost) | none for the arms | **GoalMap + ball-carrier** — GoalMap needs sk seam; carrier already injectable | **CROSS-REPO** |

`resolve_defended_goals(frames)` (sk `_gk_resolve.py:635`) = **mean GK-x per `(game, period, team)` over all unit frames**. A per-window frame slice is a smaller-sample estimator → sk's own docstring records measured per-frame-vs-full-match disagreement of **skillcorner 7.1 % / metrica 2.2 % / idsse+GS 0.0 %**. The 8 failing units are skillcorner, so a per-window GoalMap **changes the metric** — hence the invariant must be the whole-unit value (§4.3), not a per-window recompute.

`infer_ball_carrier(frames)` (sk `_ball_carrier.py:337`) is stateful: within a `(game,period)` segment it carries an `incumbent` with a hysteresis bonus (`gamma=0.25`) across consecutive frames. Independent per-window scoring resets `incumbent=-1` at each window start → divergence whenever a boundary falls mid-hysteresis. No halo bounds this (it is sequential, not fixed-radius). → whole-unit precompute + inject.

**Each mart's scoring halo must be sized to its temporal reach and proven non-vacuously sufficient (§6).** `off_ball_runs`' 1.5 s reach is the binding case — larger than the build halo for idsse/GS, though ≤ it for skillcorner (the provider of all 8 units). Regardless of that comparison, the spilled build output is halo-TRIMMED (cores only, one row per frame), so Stage-2 cannot reuse Stage-1's `_window_id`/trimmed boundaries — it **re-windows the spilled built frames with each mart's own scoring halo** (per-mart exactness, the general rationale — not "exceeds the build halo", which is false for skillcorner).

### 4.3 Whole-unit invariants: precompute once, inject (the byte-identity mechanism)
The expensive, OOM-causing work is the per-frame grids (pitch control / DAS); the whole-unit invariants are **cheap** (a mean; a per-frame carrier column) and read only position columns, not grids. Therefore:

1. **Stage-2a — invariant precompute (whole-unit, light, per unit).** Compute, over the whole unit, from a **column-pruned** read of the spilled built frames (positions / GK columns only — not the full 583 MB built frame):
   - `goal_map = resolve_defended_goals(frames)` — a tiny `(game,period,team) → defended-goal` map.
   - `carrier = infer_ball_carrier(frames)` — one row per frame (frame_id → team-in-possession), for gkdv.
   Both are sk public API already imported by the lakehouse (`gkdv_writer.py:176,231`). The peak here is positions-only columns of the unit (fit-profile gate §4.6; expected ≪ the full built frame because velocities/smoothed/derived columns and all grids are excluded). This is the only remaining whole-unit pandas pass; if even the pruned pass does not fit the densest unit, the fallback is a windowed scan with carried-forward boundary state for the carrier + a Spark groupby-mean for the GoalMap (§9 Q2).
2. **Stage-2b — windowed scoring (the expensive part).** For each scoring window, run each scorer on `(core + halo)` built frames + the entities routed to that window, **with `goal_map` / `carrier` injected** so every window uses the identical whole-unit value. Union of per-window outputs (halo-origin trimmed) = whole-unit output, byte-identical.

Injection availability by mart: `rest_defense` — sk seam exists today (lakehouse wires it). `gkdv` carrier — sk seam exists (`build_ghost_frames(..., carrier=)`, already threaded at `gkdv_writer.py:237/240`). `gkdv` GoalMap + `gk_decision` GoalMap — **require the sk seam (§4.4).**

### 4.5 Seam API + action→window routing
Reuse the ADR-089 layering (pure core in `analytics.action_context`; Spark dispatch in `ingestion`; import-linter ingestion→analytics OK):
- A Stage-2 scoring-window parameter, `_TM_SCORE_WINDOW_FRAMES` (distinct from Stage-1 `_TM_WINDOW_FRAMES`), tunable per the fit-profile.
- `score_halo_frames(mart, provider) -> int` — per-mart scoring reach (§4.2), asserted against sk params where sk-sourced (off_ball `pre_seconds`), with a module-level sentinel (ADR-067 lockstep) so an sk change to `pre_seconds` fails loud.
- The dispatch re-windows the spilled built frames by `frame_id` ordinal with the mart's scoring halo, **routes each action to the window containing its linked frame** (the asof-link is done once; an action appears as core in exactly one window), scores per window with injected invariants, trims halo-origin rows, unions.
- `build_stage2_mart_sdf` changes its group key from `["game_id","period_id"]` to `["game_id","period_id", _WINDOW_COL]` with the scoring-halo replication; `_make_streaming_group_mapper` is unchanged (it now materializes one window, not one unit).

Action routing correctness: an action's output must be produced in exactly one window (its linked frame's core window) and must see every frame its scorer reaches (within the scoring halo). The neutrality test (§6) is the gate.

### 4.6 Memory ceiling (plan gate — fit-profile)
Per-window Stage-2b peak ≈ `(core + halo)` built frames + scorer grids, bounded by `_TM_SCORE_WINDOW_FRAMES`, independent of unit size. The plan MUST fit-profile, per mart, on a real dense skillcorner unit (one of the 8): (i) the Stage-2a invariant-precompute peak (column-pruned whole-unit pass) and (ii) the Stage-2b per-window scoring peak, each ≤ the ADR budget (≤ 800 MB UDF-group working target). `_TM_SCORE_WINDOW_FRAMES` is tuned from (ii). If Stage-2a (i) does not fit, take the §9 Q2 fallback. This is measurement, not assumption (ADR-089 posture).

### 4.6a Beyond-coverage actions — out-of-contract exclusion (owner-ratified, 2026-10-12)
The windowing must be byte-identical (§Non-goal b). The implementation (neutrality gate) surfaced the one case where it cannot be: an action BEYOND the unit's frame coverage (e.g. an event logged after tracking stops) links to NO frame, so the whole-unit scorer emits only a **degenerate, frame-INDEPENDENT fallback row** for it (observed: `action_defensive` `n_defensive_credits=1`, all credit values `0.0`, for a shot 1.4 s past the last frame). A single window cannot reproduce that fallback (it derives from whole-unit context a window lacks), so windowed ≠ whole-unit for exactly those rows.

**Owner decision (2026-10-12, option 1):** treat beyond-coverage actions as **out-of-contract** and EXCLUDE them identically in both the windowed path AND the whole-unit baseline (`restrict_actions_to_frame_coverage` = drop actions that `link_actions_to_frames` cannot link to any frame; applied once per unit, both paths — `score_unit_windowed` + the production processor). In-coverage actions (every action that links — the metric population) stay byte-identical; only the degenerate beyond-coverage rows are dropped. Guarded non-vacuously by `test_coverage_guard_drops_beyond_coverage_actions_nonvacuous`.

**This is a small output-contract change vs the pre-cycle whole-unit path** (those degenerate zero-value rows no longer ship). Reconciled with Non-goal (b) above (the exception is in-coverage-byte-identical + owner-approved). **Hyrum/row-count assessment DONE (S2W-PART-01, pre-F.4 gate — `D:\Development\_reviews\2026-10-12-adr090-beyond-coverage-hyrum-assessment.md`):** MEASURED on the canary, only `action_defensive` (−1) + `defensive_credit_attributions` (−1) drop the degenerate row; `gk_decision`/`rest_defense`/`off_ball_runs` Δ=0 (frame-gated). ## 5. Why not the alternatives
- **Per-window GoalMap recompute (no injection).** A value change — skillcorner 7.1 % metric shift on exactly the 8 units. Violates Non-goal (b). Rejected.
- **Raise the UDF-group memory cap.** Serverless fixes the cap (~1 GB; AGENTS.md 1 GB UDF cap / 800 MB budget). Not raisable. Rejected.
- **Split dense units below period grain.** Blast radius into the WELDED planner pair (`_find_tracking_new_period_pairs` / `_find_idsse_new_period_pairs`), the completeness gate, replaceWhere keys, lifecycle events. Rejected (Non-goal (c)).
- **Lakehouse-only memory-reduction for gk_decision/gkdv** (column-prune + action-linked-frame filtering so their whole-unit pass fits). Owner-rejected in favour of the gold-standard sk seam; also uncertain to fit the densest units and adds custom per-mart code. Rejected per owner ruling.
- **Ship only the four lakehouse-only marts now, defer the two cross-repo marts.** Does not materialize the 8 units (gk_decision/gkdv still OOM whole-unit). Does not meet the goal. Rejected (§4.4).
- **Reuse Stage-1's build `_window_id`/halo for scoring.** The spilled build output is halo-TRIMMED to the build halo (cores only), and each mart's scoring halo is per-mart (off_ball exceeds the build halo for idsse/GS; ≤ it for skillcorner) — so the build's trimmed boundaries cannot serve scoring without re-replicating neighbour frames. ## 6. Testing & correctness
- **Per-mart neutrality (the primary gate).** For each of the six marts: union of per-window outputs == whole-unit output, value-identical, per in-scope provider, on committed fixtures forced to span ≥ 2 scoring-windows with entities straddling a boundary. The fixture MUST exercise the production path (real `match_ltr` GoalMap path for gk_decision/gkdv; injected invariants) and plant a boundary-straddling action/keeper-frame — else vacuous (the ADR-089 HFW-SPEC-03 lesson). The compares are the existing ~exact oracle (`assert_frame_equal` ≈ 1e-8). Because invariants are injected (whole-unit), neutrality is byte-identity, not a residual band.
- **Scoring-halo sufficiency (non-vacuous) — TWO complementary tests (S2W-IMPL-02 / S2W-FULL-01, rev4).** The rev1 sketch ("an entity exactly `score_halo_frames` from a boundary is identical; `score_halo_frames − 1` DIFFERS") is realized as two tests, because the literal single-frame end-to-end `halo − 1` form is vacuous on the canary (a 1-frame look-back reduction is below the `assert_frame_equal` float tolerance, and the canary has no off-ball run straddling a boundary at the ~3-window neutrality target):
  1. **Structural tightness** (`test_off_ball_halo_covers_pre_seconds_lookback_and_is_tight`, deterministic, synthetic): the off_ball halo carries EXACTLY the pre_seconds look-back `[target−halo .. target−1]` into the next window, and `halo − 1` drops the earliest look-back frame — the halo is sized to the reach and tight, not oversized.
  2. **End-to-end behavioural** (`test_off_ball_halo_is_load_bearing_end_to_end`, canary, real scorer): at a small target (200) an off-ball run's 1.5 s look-back DOES straddle a window boundary (swept 2026-10-12 — diverges at every target ≤ 200), so windowed@correct-halo == whole-unit (neutrality) while windowed@`halo=0` (look-back starved) DIFFERS — the scorer provably CONSUMES the halo frames across a boundary (not merely that the assignment carries them; the structural test is scorer-independent, this one is not).
  Together they prove sufficiency (carries the reach), tightness (halo−1 drops a frame), and behavioural dependence (halo=0 changes the scored output) — exceeding the rev1 sketch's intent.
- **Invariant-injection load-bearing — by PERTURBATION (S2W-SPEC-01, rev3).** Windowed==whole-unit alone is vacuous for the injection: no committed fixture diverges per-WINDOW (the sk ~7.1 % GoalMap figure is per-FRAME; a ~150-frame window's mean GK-x does not cross midfield, so its `resolve_defended_goals` equals the whole-unit one — asserting "per-window ≠ whole-unit" is therefore infeasible, not just unmet). The guard is instead realized the way the sk seam's own load-bearing test works — INJECT the divergence: perturb each whole-unit invariant (invert the GoalMap, scramble the carrier's possession, drop a stride survivor) and assert the windowed output CHANGES (`test_{goal_map,carrier,scored_frame_keys}_injection_is_load_bearing`). This proves `score_unit_windowed` threads the value AND the scorer consumes it; **red-green verified** — nulling the injection (goal_map/carrier/scored_frame_keys → None) fails all three (the exact "dropped injection ships green" bug B's red-green found). Composed with the sk-side load-bearing tests (the seam uses the value), the full chain is non-vacuous. The HFW-SPEC-03 "detector must be able to fail" lesson, met by perturbation rather than a (non-existent) naturally-divergent window fixture.
- **Memory / measure-before-optimize.** Invoke `mad-scientist-skills:measure-before-optimize` before touching any benchmarked scorer. Any window/scoring change re-runs `src/tests/test_benchmarks.py` (`test_bench_batched_pitch_control` / `off_ball_xt_frame` / `defcon_credit_assignment` / `line_breaking_detection` / `team_shape`; baselines `docs/performance-baselines.md`; budgets AGENTS.md — batched pitch control ≤ 5 ms/frame, line-breaking ≤ 2 ms/pass, team shape ≤ 1 ms/frame) → no latency regression. Fit-profile per §4.6.
- **Canary.** Re-run the ADR-087 preflight / a scoped drain canary on one of the 8 dense units (e.g. `1562415:1`) → no OOM, mart rows non-empty.
- **Fix B.** The 3 new `test_job_retry_policy.py` guards (§4.7); and watch the verify fail-loud on a simulated absent-field job (guards-that-cannot-fail: prove the detector is not vacuous).
- **Full suite.** All seven local gates (ruff check, ruff format --check, lint-imports, bump_wheel --check, pip_audit_ignores --check, pyright over the CI target, pytest) + `validate_workflow_cards` (the hidden 8th gate) + a real full `uv run pytest` (not `--collect-only`, not a subset).

## 7. Risks
- **R1 — sk seam dependency (highest, cross-repo).** The fix cannot complete without the sk `goal_map=` seam. Mitigation: owner coordinates with the parallel sk session; the spec states the exact required contract (§4.4); lakehouse adoption parks on the release; no lakehouse branch merge until the sk release is vendored and the floor bumped.
- **R2 — a mart is less windowable than analyzed.** The neutrality test is the gate; a mart that cannot be made neutral per-window (e.g. an unspotted whole-unit dependency beyond GoalMap/carrier) is surfaced, not shipped. Mitigation: §6 per-mart neutrality + invariant-injection equivalence.
- **R3 — Stage-2a invariant precompute does not fit the densest unit.** The pruned whole-unit pass could still be large. Mitigation: fit-profile gate (§4.6); fallback = Spark groupby-mean GoalMap + windowed carrier with carried-forward boundary state (§9 Q2).
- **R4 — scoring-halo drift.** If sk changes off_ball `pre_seconds` (or another reach), the halo must track it. Mitigation: source from sk params + a sentinel assertion (ADR-067 lockstep).
- **R5 — gkdv unchunked loop latency.** `build_keeper_observations` scores per keeper-frame in a plain Python loop (not sk's `delta_das_batch`). Windowing bounds its memory but not that latency; and re-reading the spill per window changes the IO pattern. Mitigation: measure-before-optimize (§6) — do not silently alter the loop; if the memory change touches it, benchmark and surface any budget impact (no scope creep into a perf rewrite without approval).
- **R6 — spill re-read cost.** Stage-2b re-windowing re-reads the spill with halo replication; six marts × windows. Mitigation: fit-profile / benchmark the added IO; the spill is already the Stage-2 input (ADR-088), so this is a grouping change, not a new read.
